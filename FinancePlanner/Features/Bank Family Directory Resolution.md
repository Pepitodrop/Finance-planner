# Bank Family Directory Resolution

Fixes a real, reported UX defect in the Connections setup flow (branch `feat/bank-discovery-ux`, 2026-08-21), inspired structurally (never visually/textually) by how PayPal's own bank-selection flow separates "choose a bank family" from "choose the exact branch." No PayPal branding, copy, graphics, or source was copied — see the PR description for the explicit non-goals.

## The defect

Choosing a picker tile that represents a cooperative banking family — "Volksbank / Raiffeisenbank", "Sparkasse" — opened [[Connections Page]]'s branch-search step (`InstitutionResolutionStep`) with the live search box **prefilled with that tile's literal label**. `"Volksbank / Raiffeisenbank"` is a Finance Planner-internal UX grouping, not a real ASPSP name, so the prefilled query never matched a real bank ("Volksbank Demmin", "Raiffeisenbank Grävenwiesbach", ...) and every user hit "No bank matches your search." Sparkasse happened to work by accident (the word "Sparkasse" is a literal substring of real Sparkasse branch names); Volksbank/Raiffeisenbank did not, because of the "/" and because "Raiffeisenbank" alone never appears next to "Volksbank" in one bank's name.

This was a UX correctness bug only — [[Provider Institution Selection Contract]]'s anti-guessing guarantee (the submitted `institutionId` always comes from an explicit tap on a live, server-validated directory entry) was never affected; the picker tile's literal name was never sent to any server endpoint.

## The fix

- **`src/institutions.ts`** gained an optional `directoryTerms?: string[]` field per catalogue entry (every `'ais'`/bank tile has one) — real, curated substrings/keywords used *only* to compute the resolution step's initial (blank-query) view, never sent to a provider as a query and never part of the `institutionId` validated server-side. `volksbank`'s terms are `['volksbank', 'raiffeisenbank', 'vr bank']`, split into real tokens instead of the one literal multi-word label — the exact shape of the original bug. `ing`'s terms deliberately exclude a bare `"ing"` (German city names ending "-ingen" — Reutlingen, Esslingen, Tübingen — would collide).
- **`src/features/connections/connectionsModel.ts`** gained the pure resolution logic, all covered by `connectionsModel.test.ts`:
  - `familyFilteredInstitutions(institution, liveInstitutions)` — narrows the live directory to the tile's family by matching `directoryTerms` against each candidate's normalized name/BIC/`group.name` (Enable Banking's `ASPSPGroup.name` — see [[Enable Banking]]). Falls back to the *full* directory if narrowing finds nothing, rather than asserting the bank is unsupported when the provider data hasn't proven that.
  - `familyFilterNarrowed(...)` — companion boolean so the UI can *tell* the user when that fallback happened, instead of silently widening scope (found by an independent adversarial review pass on this same branch; a silent full-directory fallback under a family tile's heading was flagged as a real, if low-severity, misconnection-risk UX gap).
  - `searchLiveInstitutions(liveInstitutions, query)` — forgiving (normalized, tokenized, accent/case/punctuation-insensitive) but non-fuzzy substring search across the whole loaded directory, used once the user types.
  - `visibleLiveInstitutions(...)` — blank query → family-scoped view; typed query → searches the *entire* loaded directory, not just the family subset, so a real bank outside the chosen family is never hidden.
  - `syntheticAisInstitution(match)` — builds a minimal, valid `Institution` from a live directory result (or a `{id: 'live-search', name: searchTerm}` placeholder), letting the new top-level search entry point (below) reach the same account-type/confirmation steps as a catalogue tile would.
- **`src/features/connections/ConnectionsPage.tsx`**:
  - `chooseInstitution()` no longer prefills `liveInstitutionQuery` with the tile's name — it opens blank, and the resolution step's blank-query view is the family-scoped directory computed above (mirrors "many concrete branches immediately visible" structurally, without copying any PayPal UI).
  - New **top-level live-directory search**: when the static catalogue's own search (`filterInstitutions`) comes up empty, an explicit "Search the full bank directory for '{term}'" action appears (only when an AIS provider actually resolves) — lets a user who typed a concrete bank Finance Planner's 11-entry static catalogue doesn't list (e.g. "Berliner Volksbank") reach it directly, without first guessing which family tile it belongs to. Reuses the exact same resolution UI/security contract; the user's own typed text is real free-text input here (not a synthetic label), so prefilling the search box with it is correct, unlike the family-tile case above.
  - **Retry** for a failed live-directory fetch (previously only the cross-provider fallback existed, no way to retry the same provider).
  - Richer empty/loading states: a stable-height skeleton loading list (`role="status" aria-live="polite"` on the persistent list container, not on conditionally-inserted children — a live region only reliably announces changes to an already-present node), and an "Add a manual account instead" action alongside the existing "All institutions" back link and cross-provider fallback.
  - `loadLiveInstitutions()` gained the same generation-counter stale-response guard `loadProviderStatus()` already had (found by an independent adversarial review pass: four separate call sites — `chooseInstitution`, the new `searchLiveDirectory`, `useGoCardlessFallback`, `retryLiveInstitutions` — could otherwise race). Bounded impact even before the fix: both providers' `start()` re-validate the submitted `institutionId` against their own live directory and reject a mismatch, so a stale response could never connect the wrong bank, only surface a confusing error.
- **`server/src/providers.js`**: `sanitizeEnableBankingAspsp()` now passes through Enable Banking's `group: {name, logo}` field, sanitized to that exact shape (see [[Enable Banking]]) — the real provider metadata `familyFilteredInstitutions()` above prefers when available. GoCardless institutions never carry `group`; the family match falls back to matching the bank's own name/BIC there, which already works for GoCardless's directory naming.

## What this deliberately does not do

- Does not issue a literal provider search for an umbrella label like "Volksbank / Raiffeisenbank" — the group label is a Finance Planner UX concept, matched client-side against real directory metadata, never sent upstream as a query (`GET /aspsps` takes `country`/`psu_type`/`service`/`payment_type`, no group filter).
- Does not expand the CI production-acceptance fixture matrix (`connectionsAcceptanceFixtures.ts` / `scripts/connections-production-acceptance.mjs`) with new modes for the resolution step — a deliberate scope boundary, see Verification below.
- Does not render `group.logo` or the pre-existing `ProviderInstitution.logo` field anywhere — both are sanitized, typed, and unused client-side by design, consistent with [[Connections Page]]'s existing "reviewed logos only, never an unreviewed third-party image URL" institution-branding policy.

## Verification

- **Unit/component: yes.** `src/institutions.test.ts`, `src/features/connections/connectionsModel.test.ts` (new `familyFilteredInstitutions`/`familyFilterNarrowed`/`searchLiveInstitutions`/`visibleLiveInstitutions`/`syntheticAisInstitution` suites), `src/features/connections/ConnectionsPage.test.tsx` (new "bank-family resolution" and "top-level search reaching a concrete live bank" suites, plus the Retry/empty-state/unnarrowed-notice cases) — all passing, including the exact reported-bug regression case (Volksbank/Raiffeisenbank opens blank and shows real branches immediately).
- **Server: yes.** `server/test/enable-banking-directory.test.js` gained cases for `group` sanitization (passthrough, omission-when-absent, omission-when-nameless, no unreviewed upstream fields leak).
- **Real browser, modal/scroll/mobile mechanics: yes, locally.** Ran the project's own `scripts/run-connections-production-acceptance-stable.mjs` against a real `postgres:17-bookworm` container + `AUTH_MODE=local` connector + `vite preview` production build, headless Chromium (Playwright's bundled `chromium_headless_shell`, `CHROME_BIN` override) — all 14 existing acceptance modes passed, 74 screenshots, zero browser errors, confirming the "exactly one scroll region" contract ([[Connections Page]]) and mobile-nav/touch-target/dialog-containment assertions still hold with this branch's CSS/DOM changes.
- **Real browser, the new institution-resolution screen specifically: no.** None of the 14 existing acceptance fixture modes drive into `InstitutionResolutionStep` (the branch-search screen), and reaching it live requires the AIS tile to resolve as available/configured — no Enable Banking or GoCardless credentials exist in this environment (matches [[Provider Status]]'s existing unverified state for both). Extending the acceptance fixture matrix to cover this screen was deliberately left out of this branch's scope (see above) rather than rushed.
- **Live sandbox consent/callback/sync: unaffected, still unverified.** This change is institution-*discovery* UX only; it does not touch `start()`/`completeCallback()`/`sync()` for either provider. See [[Enable Banking]] / [[GoCardless]] / [[Provider Status]] — still `IMPLEMENTED`, not `SANDBOX CONSENT VERIFIED`.

## Independent review

An adversarial review pass (Claude subagent + gstack specialist dispatch: testing/maintainability/security) on this branch found and led to fixes for: the `loadLiveInstitutions` generation-guard gap above, the silent-full-directory-fallback signal (`familyFilterNarrowed`), and an `aria-live` region regression (a loading/results region that only existed while content changed, rather than a persistent node — screen readers don't reliably announce a freshly-inserted node with content already in it). Confirmed clean: no path lets a client-fabricated/synthetic institution id reach `startConnector()` instead of an explicit tap on a real, server-fetched directory row (`connectorContext()` always sources `institutionId` from `resolvedProviderInstitution`, set only by `finalizeInstitutionResolution()` on a real tap); no XSS/injection surface from the new `group.name`/free-text search fields (no `dangerouslySetInnerHTML`, no server-side sink for the search query). A Codex adversarial pass was attempted but timed out without producing output — treated as missing coverage, not a clean bill, per [[Memory System]]'s evidence-honesty rule.
