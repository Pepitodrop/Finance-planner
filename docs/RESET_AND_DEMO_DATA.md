# Finance-data cleanup and explicit test seeding

Finance Planner no longer ships or provisions a demo finance dataset. Production defaults are empty, test-account provisioning creates identity only, and test finance data is added only by an explicit operator command.

## Clear all financial/provider data while keeping authentication

The cleanup tool removes financial and connector state from:

- `user_finance_state`
- `user_budget_learning_profiles`
- `connector_connections`
- `oauth_nonces`
- `webhook_events`

It deliberately preserves `auth_store`, session-revocation state, rate-limit state, and migration history. This means sign-in identity, display name, passkeys, and the personalized dashboard greeting can remain while accounts, transactions, goals, provider connections, and learned finance data are removed.

Preview first:

```bash
cd server
npm run database:clear-finance:dry-run
```

Execute only with the explicit destructive confirmation:

```bash
export CLEAR_FINANCE_DATA_CONFIRM=DELETE_ALL_FINANCE_DATA_KEEP_AUTH
npm run database:clear-finance
```

After server-side cleanup, any device that still has a non-empty encrypted local vault can re-upload that data when the vault is unlocked. Reset the local vault to empty before the server cleanup, or deliberately remove/recreate the local encrypted vault, when the goal is a completely clean financial starting point.

## Provision the test identity

```bash
cd server
npm run test-account:provision
```

This creates or verifies the configured test identity only. It does not create accounts, balances, transactions, goals, or learning data.

## Seed deterministic test finance data

The test dataset is generated by `core/cobol/test-data-seed.cob`. GnuCOBOL owns the deterministic finance records; Node.js only parses/validates them, resolves the configured test identity, encrypts the payload, and performs the PostgreSQL upsert.

Dry run:

```bash
cd server
npm run test-account:seed:dry-run
```

Seed the configured test account:

```bash
npm run test-account:seed
```

The seeder fails closed unless `TEST_ACCOUNT_EMAIL` resolves to an existing user whose internal id starts with `test:`. It will not seed a Google/password production user by accident.

In the production container the generator is compiled to `/app/build/test-data-seed`, and the orchestration script is `/app/scripts/seed-test-account.mjs`.

## Production invariant

A normal Finance Planner account starts with no accounts, no transactions, and no goals. Acceptance/screenshot fixtures are test harness data only and are not production defaults. Authentication records are not financial data and remain necessary for login, passkeys, and the user's display name.
